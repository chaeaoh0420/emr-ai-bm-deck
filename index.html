리비짓 · 애프터닥은 환자를 검색·입력하고 템플릿을 선택해야 하지만,

Definition

"재진환자 관리"의 정의와 범위

진료 종료 후 환자가 다시 내원해야 하는 시점·사유를 의원이 사전에 식별하고,
적절한 시점에 환자에게 안내(메시지/콘텐츠/예약)를 전달하여 재방문으로 연결하는 일련의 운영 흐름.
01
정기 추적 안내
검진·내시경·초음파·만성질환 정기 추적 시점 도래 시 안내
02
검사 결과 호출
검사 결과 이상치 환자 선별 → 예정일보다 빠른 재내원 안내
03
처방 후속 안내
약 떨어질 시점 안내, 다회차 접종·주사 시점 안내
04
검진 자격 활용
공단검진 미수검자·가감 대상자·하반기 대상자 안내
05
만성질환 관리
일만제 환자 정기 교육·상담·검사 시점 안내
!
핵심 포인트
단순 마케팅 메시지가 아닌, 진료 연속선상의 환자 커뮤니케이션

A. 외부 솔루션 사용형

분류 A — 페인포인트 · 도출된 니즈

의사랑 CRM 가치를 명확히 인지하고 외부 솔루션에 비용을 지불 중인 의원

서초연세내과
애프터닥 월 25만
PAIN POINT
  • 의사랑 CRM "왜 있는지도 모르겠다" — 미사용
  • 매일 진료 종료 후 환자 정보 일일이 수기 입력 (700명/일)
  • 차트 ↔ 애프터닥 동시 띄움 + 차트 대조 수동 태그 라벨링 (50명/10분)
  • 발송 이력 차트 누락 → 의무기록 단절
  • 전화번호 오기입 시 타인 검사결과 전송 위험
  • 월 25만원 + 브랜드 메시지 별도 단가 부담
NEED
  • 차트 등록 = CRM DB 등록 자동 연동 — DB 등록 노가다 제거
  • 차트 기반 환자 식별 — 잘못된 발송 위험 제거
  • 발송 이력 차트 자동 누적 — 의무기록 보장
  • 검사 결과지·진단서·처방전 등 파일 발송 통합
연수이이주내과
뿌리오 별도 결제
PAIN POINT
  • 종이 장부 5종 + 엑셀 + CRM 전담 1명 운영
  • 원장 워드 정리 → CRM 전담 직원 차트 매칭 → 발송 (4단계 수기)
  • 검진 대상자 일괄 발송은 외부 뿌리오 별도 처리 (의사랑 미지원)
  • 발송 이력이 워드 파일에만 저장
  • 검사 결과 이상치 환자 호출 워크플로우 별도 페인 — 매주 월요일 차트 일일이 재오픈
NEED
  • 종이장부·워드 → 시스템 통합 — 4단계 수기 작업 제거
  • 검사 결과 이상치 자동 알림 + 차트 일괄 뷰
  • 시점별 시나리오 자동 발송 (헬리코박터·내시경·초음파)
SUMMARY · A 의사랑 CRM 가치 부재 → 외부 솔루션에 월 비용을 지불해도 차트 비연동·수기 환자 등록·수기 반복되는 템플릿 선택이라는 구조적 한계 잔존

B. 자체 우회 시스템 운영형

분류 B — 페인포인트 · 도출된 니즈

의사랑 CRM 한계를 우회하기 위해 자체 약어·메신저·종이장부 체계를 구축

지인내과의원
이지스 약어 체계
PAIN POINT
  • 원장 약어(C1·C3·G1) → 원무 약어 확인 → CRM 검색·발송 → 차트 기록 (4단계)
  • "이지스에는 있고 의사랑에는 없는 기능" — 약어 입력 → 자동 발송 + 차트 기록
  • "기능은 있지만 실사용 불가" — 통계·청구·재고 누적 미해결 페인
  • 원장: 진료실 팝업 거부감 → 원무 처리 분담 강함
NEED
  • 약어 입력 → 자동 발송 + 차트 기록 통합 (이지스 표준 기능)
  • 원무 진입 경로 보존 — 원장이 진료실에서 약어만 내리면 원무가 후속 처리
창동제일의원
CRM 활용도 한계
PAIN POINT
  • 외래·검진·환자관리 시스템 분리
  • CRM 조건 항목 과다 (예약일·검사·생년월일·상병…) — 교집합 모름
  • 안 쓰는 조건 다 노출 → 직관성 떨어짐
  • 의사별 이상소견 기준 다름 → 일률적 자동화 불가
  • 예약 등록 ≠ 안내 메시지 자동 연결 → 이중 작업
  • 우회: 엑셀 추출 → 분류 → 재업로드
NEED
  • 예약 등록 = CRM 발송 = 진료실 팔로업 등록의 구조적 통합
  • 의사·과 단위 팔로업 규칙 독립 설정
  • 자주 쓰는 조건 중심 단순 UI + 필요 시 교집합 조합 유연성
  • 공단·심평원 자격 연동 — 분변잠혈 양성·하반기 검진 대상자 자동 추출
서울윤내과 · 서울굿모닝내과
카카오워크 이중 동선
PAIN POINT
  • 진료실(원장) ↔ 원무 화면 분리 → 카카오워크로 별도 지시
  • 원무가 의사랑 CRM 별도 창 열어 환자 검색·발송
  • 도입 3년 이내 신규 고객사임에도 기본 기능 "없다고 안내받아 미사용" → 발견성 한계
  • 약 떨어질 시점 자동 안내 니즈 명확
NEED
  • 진료실 증상 메모만으로 팔로업 자동 등록 → 원무 별도 작업 없이 발송 연결
  • 시점 기반 자동 발송 (약 처방·재방문)
  • 사용자 통제권 보존 — 메시지 발송은 자동화하되 예약 날짜는 사용자 판단
SUMMARY · B 의사랑 CRM 한계 → 자체 약어·메신저·종이장부 체계를 별도 구축해 우회 운영 중 → 표준 EMR 기능으로 흡수되면 즉시 전환 가능

C. 재진환자 관리 미운영형

분류 C — 페인포인트 · 도출된 니즈

진료 도메인 특성이나 시스템 부담으로 재진환자 관리 자체를 운영하지 않거나 구두 안내에만 의존

365류마고내과
재진율 낮음
PAIN POINT
  • 재진 환자 놓침 = 매출 절반 손실 추정 (원무팀장)
  • "안 아프면 안 오는" 환자 특성 (통풍·자가면역)
  • 자가면역질환 관리 시스템 부재 → 원장 개인 역량 의존
  • 진료 3~5분 → 클릭 한 번·컨펌 한 번 수준이어야 도입 가능
NEED
  • 광고성 아닌 진료 연속선상 안내
  • 질환·환자 특성 기반 개별화된 재진 관리
  • 진료실 단일 동선 통합 (원무 분담 불가)
고려제일내과
어르신 위주
PAIN POINT
  • 환자 다수 어르신 → 문자·카톡 실효성 낮음
  • 재검 시기 안내는 구두 전달만
  • 의사랑 일만제 메뉴 분산 → 웰체크로 회피
NEED
  • 차트 진입 시 "재검 시기 도래" 알림 — 구두 안내 보조 형태
  • 원장이 정리하는 환자 리스트 자동 추출
  • 일만제 통합 화면 (가입·교육·메시지)
성모혜민내과
인공신장실 1:1
PAIN POINT
  • 인공신장실 환자 1:1 매칭 관리 → 시스템 팔로업 불필요
  • 일반진료는 외부 유료 문자 시스템 사용 중
  • 명시적 페인 표현 없음
NEED
